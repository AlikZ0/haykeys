# HayKeys: армянская клавиатура для iPhone

Версия **1.3, сборка 6**. Приложение и расширение на Swift / UIKit, iOS 16+. Собственный Mac не обязателен: используйте существующую сборку GitHub Actions и установку через SideStore. ZIP содержит исходники; для iPhone нужен заново собранный IPA.

## Что изменено в версии 1.3

- Удалена вся верхняя панель слов: ни готовых фраз, ни подсказок над клавишами больше нет.
- `և` перенесена на место `-` в первом ряду. Дефис остаётся на странице цифр. Буквы `ե`, `է`, Shift → `Ե` сохранены.
- Кнопка смайлика и встроенная панель эмодзи удалены. `123` расширена примерно до суммарной ширины двух прежних кнопок. Основной нижний ряд: `123`, пробел, ввод. Когда iOS требует кнопку смены клавиатуры, добавляется глобус.
- Убран непрозрачный фон и искусственное скругление верха HayKeys. Для фона используется `UIInputView.Style.keyboard` с системным размытием и оттенком. Тёмные клавиши слегка прозрачны. Нижняя область глобуса/микрофона остаётся под управлением iOS; точное совпадение с системной клавиатурой не гарантируется.
- Первый ряд больше не прижат к верхней границе: отступ 16 пунктов в портретном положении и 8 в альбомном. Этот отступ входит в высоту расширения.
- Убран добавочный учёт нижней безопасной области: высота HayKeys больше не увеличивается на `safeAreaInsets.bottom`, а последний ряд привязан к нижней границе самого расширения без добавочного отступа. Системную нижнюю область по-прежнему формирует iOS. Её точное совпадение с системной клавиатурой на iPhone здесь не подтверждено.
- Для альбомного положения ширина рядов и их центрирование рассчитываются по одной и той же безопасной горизонтальной области. Клавиши в портретном положении уменьшены с 42 до 38 пунктов, промежутки между рядами — с 8 до 6; собственный нижний отступ теперь 0. Высота расширения: 230 пунктов в портретном положении и 182 в альбомном. Системная область iOS в эти числа не включена.
- В самом приложении добавлена история последних 100 разных текстов, сохранение на устройстве, повторное копирование, удаление одной записи и очистка всей истории.

## Звук клавиш

Штатный щелчок iOS включён в HayKeys по умолчанию. Используется `UIDevice.playInputClick()` и `UIInputViewAudioFeedback`, без записи аудио и управления аудиосессией. Звук слышен только при разрешённом системном звуке клавиатуры; режим «Без звука» и громкость также влияют на результат. HayKeys не включает звук других клавиатур и не меняет их настройки.

Чтобы отключить звук:

1. Откройте приложение **HayKeys → Звук клавиш**.
2. Выключите **«Щелчки HayKeys»** и нажмите **«Применить к клавиатуре»**.
3. В открывшейся клавиатуре через глобус выберите **HayKeys Armenian**. Если она уже выбрана, подождите подтверждения.
4. Дождитесь сообщения **«Подтверждено HayKeys: звук выключен»**. Только оно подтверждает, что настройка принята расширением. Затем проверьте ввод в поле приложения.

Для повторного включения выполните те же шаги с включённым переключателем. Пока отображается просьба выбрать HayKeys, изменение ещё не подтверждено. Можно отменить применение и повторить. Если системный звук выключен, включённый переключатель HayKeys не обходит это ограничение.

Настройка передаётся только во время явного применения через служебное поле ввода самого приложения, с одноразовым идентификатором запроса и ответом клавиатуры. В расширении хранится только признак включения звука в его собственных настройках. Общий контейнер, App Groups, полный доступ, сеть и дополнительная настройка подписи не нужны. Настройка сохраняется после закрытия клавиатуры.

[Документация Apple по щелчку клавиш](https://developer.apple.com/documentation/uikit/uidevice/playinputclick()).

## Как обновить установленную клавиатуру

1. Распакуйте архив. В репозитории GitHub замените `App`, `Core`, `Keyboard`, `Tests`, `scripts` и `HayKeys.xcodeproj` содержимым архива, а также обновите корневой `PrivacyInfo.xcprivacy`. **Свой `Config/Personal.xcconfig` и Bundle Identifier сохраните.** Рабочий workflow менять не нужно.
2. Запустите прежнюю сборку GitHub Actions. Она выполнит проверки ядра и соберёт приложение с расширением. Скачайте новый IPA из артефакта успешного запуска.
3. Установите через SideStore поверх HayKeys с тем же Apple Account, сохранив `HayKeysKeyboard.appex`. Не удаляйте приложение перед обновлением, если уже пользуетесь историей буфера.
4. В приложении должна отображаться версия **1.3**. В «Заметках» переключите клавиатуру на другую и обратно; при необходимости перезапустите «Заметки».
5. Проверьте отсутствие верхних слов, `և` вместо дефиса, широкую кнопку `123`, первый ряд и расстояние до системного глобуса/микрофона, тёмное оформление App Store и Safari, затем светлое оформление и поворот экрана.

## История буфера: что сохраняется

Для сохранения скопированного текста откройте **HayKeys → История буфера** и нажмите системную кнопку **«Вставить»**. Текущее содержимое буфера попадёт в историю. На главном экране кнопка **«Копировать и сохранить весь текст»** копирует всё содержимое поля проверки и сразу сохраняет его в историю.

Хранятся последние 100 **разных текстов**, новые сверху. Повторное добавление перемещает текст в начало. Пробелы, переносы строк и эмодзи сохраняются без обрезки. Пустые строки игнорируются. Изображения и файлы не сохраняются. Записи доступны после перезапуска приложения. Файл хранится в контейнере приложения с системной защитой файла и исключён из резервной копии; сеть и синхронизация не используются. Удаление приложения удалит историю.

**Автоматического сохранения каждого нажатия «Скопировать» в других приложениях нет.** Клавиатура не получает события системного меню копирования, не может постоянно работать в фоне и не восстанавливает уже заменённые значения буфера. Полный доступ для текущей реализации не требуется. История приложения не доступна из панели клавиатуры.

Ограничение меню копирования описано в [документации Apple](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/CustomKeyboard.html). [Системный стиль фона клавиатуры](https://developer.apple.com/documentation/uikit/uiinputview/style/keyboard) предоставляет размытие и оттенок, но внешний вид зависит от версии iOS и приложения.

## Управление

Все 38 отдельных армянских букв сохранены; `և` добавлена отдельно. Одно нажатие Shift включает заглавную букву, два быстрых — Caps Lock. Удержание `ե` вводит `և`, `ւ` — `ու`. Удержание удаления повторяет удаление; удержание пробела с движением пальца перемещает курсор. Удержание ввода скрывает клавиатуру. На устройствах, где iOS требует кнопку смены языка, глобус появляется в нижнем ряду.

## Установка без собственного Mac

Полная инструкция для Ubuntu, GitHub Actions и SideStore приведена ниже. Если используете Markdown-файл, можно открыть отдельный `INSTALL_NO_MAC_RU.md`.

Нужны Ubuntu с USB-портом, iPhone, Wi-Fi, аккаунты GitHub и Apple Account. Проект собирает macOS-сервер GitHub Actions. Затем SideStore подписывает IPA вашим аккаунтом и устанавливает его. Локально Xcode на Ubuntu не запускается.

На предыдущем скриншоте GitHub Actions виден успешный запуск с артефактом, а на новых скриншотах — уже установленная клавиатура. Для обновления используйте раздел «Как обновить установленную клавиатуру» выше; повторять первоначальную настройку SideStore не требуется.

### 1. Соберите IPA на GitHub

1. Распакуйте архив. Рабочая папка называется `HayKeys`.
2. На GitHub создайте репозиторий, например `haykeys`. Для бесплатных стандартных runners выберите **Public**: исходники станут общедоступными. Можно включить создание README при создании репозитория.
3. Нажмите **Add file → Upload files** и загрузите **содержимое** папки `HayKeys`. В корне репозитория должны оказаться `App`, `Core`, `Keyboard`, `scripts`, `Tests`, `Config`, `HayKeys.xcodeproj` и остальные файлы. Загружать только ZIP не нужно: GitHub его не распакует.
4. В репозитории должен быть файл **`.github/workflows/build-ipa.yml`** из архива. Если он не попал в загрузку, нажмите **Add file → Create new file**, задайте этот путь и вставьте содержимое одноимённого файла из проекта. Сохраните в основной ветке.
5. Откройте **Actions → Build HayKeys IPA → Run workflow**. Если GitHub попросит включить Actions, включите их. В ветке `main` сборка также запускается после загрузки файлов автоматически.
6. Дождитесь зелёного статуса. Workflow сначала проверяет логику клавиатуры, затем собирает приложение и расширение для реального iPhone.
7. Внизу страницы запуска, в разделе **Artifacts**, скачайте **HayKeys-unsigned-IPA**. Распакуйте загруженный ZIP: внутри будет **HayKeys-unsigned.ipa**.

Для GitHub Actions не нужны пароль Apple Account, сертификаты или платный аккаунт Apple Developer. Workflow выполняет сборку без подписи. Для публичного репозитория со стандартным runner GitHub не взимает плату за время сборки. Артефакт хранится 3 дня; в проекте не используются платные larger runners.

Если сборка красная, откройте упавший шаг. IPA появится только после успешной сборки. Не продолжайте установку с другим случайным IPA. В этом случае нужен фактический текст ошибки GitHub Actions.

### 2. Подготовьте Ubuntu и SideStore

1. Установите поддержку подключения iPhone:

```bash
sudo apt update
sudo apt install usbmuxd
```

2. На <https://iloader.app/> выберите **Linux (x86_64) → Ubuntu/Debian (.deb)**. После скачивания откройте терминал в папке с файлом и выполните:

```bash
sudo apt install ./iloader-linux-amd64.deb
```

3. На iPhone установите бесплатный [LocalDevVPN](https://apps.apple.com/app/localdevvpn/id6755608044). Подключитесь к Wi-Fi. Подключите телефон кабелем к Ubuntu, разблокируйте его и подтвердите доверие компьютеру.
4. Запустите **iloader**, войдите в Apple Account, выберите телефон и нажмите **Install SideStore (Stable)**.

Пароль Apple Account вводится в инструменты установки, а не в GitHub. Файлы сопряжения телефона и сертификаты в публичный репозиторий не загружайте.

Официальная инструкция подготовки Linux: <https://docs.sidestore.io/docs/installation/prerequisites>.

### 3. Завершите настройку SideStore на iPhone

Этот этап выполняется после установки SideStore через iloader из предыдущего раздела. Успешная сборка на GitHub сама по себе ничего не устанавливает на телефон и не показывает «Режим разработчика» в его настройках.

1. Откройте **Настройки → Основные → VPN и управление устройством**, выберите профиль своего Apple Account и подтвердите доверие. На новых iOS система может показать **«Разрешить и перезагрузить»**; подтвердите и введите код телефона.
2. Откройте **Настройки → Конфиденциальность и безопасность**, прокрутите до самого конца и найдите **«Режим разработчика»**. Если пункт есть, включите его, перезагрузите iPhone и подтвердите включение после перезагрузки. Если пункта нет, выполните действия ниже.
3. В **LocalDevVPN** нажмите **Connect**.
4. Откройте **SideStore** и войдите в тот же Apple Account, который использовали в iloader.
5. В **My Apps** нажмите счётчик дней около SideStore, чтобы проверить продление его подписи.

Точные шаги по версиям iOS: <https://docs.sidestore.io/docs/installation/install>.

#### Если пункта «Режим разработчика» нет

На iOS 16 и новее этот пункт может быть скрыт. Сначала попробуйте открыть установленный SideStore, затем полностью закройте приложение «Настройки» и откройте его заново. Если пункт по-прежнему отсутствует, запросите его показ с Ubuntu:

1. Установите инструмент в отдельное Python-окружение. Эти команды выполняются **на Ubuntu**, а не на iPhone:

```bash
sudo apt update
sudo apt install python3-venv usbmuxd
python3 -m venv ~/haykeys-tools
~/haykeys-tools/bin/python -m pip install -U pymobiledevice3
```

2. Подключите iPhone USB-кабелем, разблокируйте его и подтвердите **«Доверять этому компьютеру»**, если появится запрос. Проверьте подключение:

```bash
~/haykeys-tools/bin/python -m pymobiledevice3 usbmux list
```

Если список пустой, переподключите кабель и снова проверьте телефон. Пока устройство не обнаружено, к следующей команде не переходите.

3. Запросите показ переключателя в настройках:

```bash
~/haykeys-tools/bin/python -m pymobiledevice3 amfi reveal-developer-mode
```

4. Полностью закройте «Настройки» на iPhone. Откройте **Настройки → Конфиденциальность и безопасность**, прокрутите вниз и проверьте **«Режим разработчика»**.
5. Включите переключатель, согласитесь на перезагрузку, затем подтвердите включение на iPhone и введите код блокировки.
6. Вернитесь к настройке SideStore: LocalDevVPN → Connect → SideStore → вход в тот же Apple Account.

`reveal-developer-mode` только запрашивает показ пункта; включение и перезагрузку подтверждает владелец телефона. Команда проверена по CLI и исходникам pymobiledevice3 11.45.0, но на вашем iPhone она ещё не выполнялась. Если команда выдаёт ошибку или пункт всё равно не появился, нужны её точный вывод и версия iOS из **Настройки → Основные → Об этом устройстве**.

Документация и исходники: <https://doronz88.github.io/pymobiledevice3/installation/>, <https://doronz88.github.io/pymobiledevice3/cli/amfi/>, <https://github.com/doronz88/pymobiledevice3/blob/master/pymobiledevice3/services/amfi.py>.

### 4. Установите HayKeys

1. Сохраните **HayKeys-unsigned.ipa** в приложение **«Файлы»** на iPhone. Например, откройте GitHub Actions в Safari, войдите в свой GitHub и скачайте Artifact прямо на телефоне; ZIP можно распаковать нажатием в «Файлах».
2. С подключёнными Wi-Fi и LocalDevVPN откройте **SideStore → My Apps → +**, выберите IPA и дождитесь подписания и установки.
3. Если установщик предложит удалить расширения приложения, **оставьте HayKeysKeyboard.appex**. В нём находится клавиатура; установка только основного приложения не даст возможности печатать в других приложениях.
4. Откройте HayKeys. Затем перейдите в **Настройки → Основные → Клавиатура → Клавиатуры → Новые клавиатуры** и добавьте **HayKeys Armenian**. Полный доступ не нужен.
5. Откройте «Заметки», нажмите текстовое поле, удерживайте **🌐** и выберите **HayKeys Armenian**.

Неподписанный IPA сам по себе не устанавливается нажатием в «Файлах». Подпись создаёт SideStore во время установки. Внешний вид и названия элементов SideStore могут отличаться между версиями.

### 5. Продлевайте подпись до истечения 7 дней

У бесплатного аккаунта остаётся срок подписи **7 дней**. До его истечения включите Wi-Fi и LocalDevVPN, откройте SideStore и обновите **HayKeys и сам SideStore** в My Apps. Повторная облачная сборка для обычного продления не нужна. Если подпись SideStore уже истекла, может потребоваться повторная установка через iloader с Ubuntu.

Лимиты бесплатного аккаунта: до 3 активных установленных таким способом приложений, включая SideStore, и до 10 App IDs за 7 дней. Расширения требуют App IDs. Детали: <https://docs.sidestore.io/docs/faq>.

### Если достаточно готовой клавиатуры

В армянском App Store есть бесплатная [Armenian Keyboard+](https://apps.apple.com/am/app/armenian-keyboard/id6753932933) с Eastern и Western Armenian. Она не требует Mac и еженедельной переподписи через SideStore. Точное совпадение её текущей раскладки со скриншотом не подтверждено.

Установите приложение, затем добавьте его в **Настройки → Основные → Клавиатура → Клавиатуры → Новые клавиатуры** и выберите через 🌐. По описанию разработчика, полный доступ не требуется.

## Локальная установка через Xcode, если есть доступ к Mac

### 1. Подготовьте Mac

1. Установите Xcode из Mac App Store. Официальная страница: <https://developer.apple.com/xcode/>.
2. Откройте Xcode и завершите первичную настройку. Если предложит установить компоненты iOS, установите их.
3. Версия Xcode должна поддерживать iOS вашего iPhone. Если система телефона новее поддерживаемой версии, потребуется обновление Xcode и, возможно, macOS.
4. В меню **Xcode → Settings → Accounts / Apple Accounts** добавьте свой Apple Account. Если платной подписки разработчика нет, Xcode покажет **Personal Team**. Примите соглашение разработчика, если Apple его предложит.

### 2. Откройте проект

1. Распакуйте ZIP на Mac, например в `Downloads`.
2. В распакованной папке `HayKeys` дважды нажмите **HayKeys.xcodeproj**.
3. Откройте `Config/Personal.xcconfig` в левом списке файлов Xcode.
4. Замените `com.alik.haykeys` своим идентификатором, если он уже занят. Пример формы: `com.yourname.haykeys123`. Используйте латинские буквы, цифры и точки. Никаких доменов покупать не нужно.

```xcconfig
HAYKEYS_BUNDLE_ID = com.yourname.haykeys123
```

Меняйте только значение `HAYKEYS_BUNDLE_ID` в этом файле. Идентификатор приложения возьмёт это значение, а идентификатор расширения автоматически получит суффикс `.keyboard`. Это сохраняет необходимую связь между ними.

### 3. Настройте подпись для двух targets

1. Нажмите синий значок проекта **HayKeys** в левом списке Xcode.
2. В разделе **TARGETS** выберите **HayKeys**.
3. Откройте **Signing & Capabilities**.
4. Включите **Automatically manage signing** и выберите свою **Personal Team** в поле **Team**.
5. Повторите те же действия для второго target: **HayKeysKeyboard**.
6. Дождитесь, пока Xcode создаст профили подписи. Для этого на Mac нужен интернет.

При ошибке `Signing requires a development team` команда не выбрана для одного из targets. При `Bundle Identifier is not available` поменяйте значение в `Config/Personal.xcconfig`, затем повторите сборку. Платные возможности и App Groups подключать не нужно.

### 4. Подключите iPhone

1. Подключите iPhone к Mac USB-кабелем и разблокируйте его.
2. Если появится вопрос «Доверять этому компьютеру?», нажмите **Доверять** и введите код телефона.
3. Выберите iPhone в списке устройств рядом со схемой запуска вверху Xcode. Если его нет, откройте **Device Hub**; в старых Xcode это **Window → Devices and Simulators**. Дождитесь завершения сопряжения и подготовки.
4. На iPhone откройте **Настройки → Конфиденциальность и безопасность → Режим разработчика**.
5. Включите режим, перезагрузите iPhone и после перезагрузки подтвердите включение.

Если пункта «Режим разработчика» нет, сначала начните сопряжение телефона с Xcode. По документации Apple этот пункт появляется после начала сопряжения или если телефон ранее был сопряжён с Mac.

### 5. Установите приложение

1. В верхней панели Xcode выберите схему **HayKeys**, а устройством запуска — свой физический **iPhone**. Не выбирайте HayKeysKeyboard как основную схему установки.
2. Нажмите **▶ Run** или **⌘R**.
3. Дождитесь сборки. На iPhone должно запуститься приложение **HayKeys**. Расширение клавиатуры устанавливается внутри него.
4. Если iOS отдельно попросит довериться разработчику, откройте **Настройки → Основные → VPN и управление устройством**, выберите свой профиль разработчика и подтвердите доверие. Этот дополнительный шаг нужен только если система его запрашивает.

### 6. Добавьте клавиатуру в iOS

1. На iPhone откройте **Настройки → Основные → Клавиатура → Клавиатуры → Новые клавиатуры**. В некоторых переводах последний пункт называется «Добавить новую клавиатуру».
2. В разделе сторонних клавиатур выберите **HayKeys Armenian**.
3. «Полный доступ» для этого проекта не нужен. Переключателя может не быть, поскольку расширение его не запрашивает.
4. Откройте приложение «Заметки» или поле проверки в HayKeys и нажмите в текстовое поле.
5. Удерживайте **🌐** на текущей клавиатуре и выберите **HayKeys Armenian**.
6. Напишите `Բարև, շնորհակալություն։`, затем проверьте Shift, удаление и переключение обратно через 🌐.

После установки Mac не нужен для повседневного ввода. Он понадобится для следующего продления подписи.

### 7. Продлевайте бесплатную подпись

Профиль Personal Team истекает через **7 дней с момента выдачи**. После истечения приложение и расширение могут перестать запускаться.

Для продления подключите тот же iPhone к Mac, откройте тот же проект с тем же Apple Account и идентификатором, затем снова нажмите **⌘R**. Удалять приложение заранее не нужно. Не меняйте идентификатор каждую неделю: это создаёт лишние App IDs.

Apple также ограничивает Personal Team количеством приложений, устройств и App IDs. Если Xcode сообщит о лимите, проверьте текущие бесплатные установки и срок действия регистраций по ссылке Apple внизу. Отдельного бесплатного режима «установить навсегда» у этого способа нет.

## Проверка и известные ограничения

В среде, где подготовлен архив, нет macOS, Xcode, iOS SDK и подключённого iPhone. Проверены синтаксическая структура Swift отдельным парсером, формат Xcode-проекта, ссылки на исходники и ресурсы, plist и соответствие набора букв. **Сборка Apple Swift-компилятором, запуск модульных проверок Swift, симулятор и ввод на физическом iPhone здесь не выполнялись.** Отсутствие синтаксических ошибок не подтверждает успешную сборку или работу интерфейса на устройстве.

Также проверены формат workflow и синтаксис shell-скриптов облачной сборки. На скриншоте пользователя виден успешный запуск GitHub Actions с одним артефактом. Логи и содержимое IPA в этом запуске не проверены. На новых скриншотах пользователя клавиатура уже установлена. Новую версию 1.3 и её оформление нужно проверить после обновления.

На Mac можно выполнить проверку ядра и сборку для симулятора без подписи:

```bash
cd ~/Downloads/HayKeys
bash scripts/check_macos.sh
```

Если папка распакована в другое место, укажите её фактический путь. Команда запускает проверки в `Tests/main.swift`, затем собирает оба targets через `xcodebuild`. При ошибке исправление нужно делать по фактическому выводу Xcode; успешный результат скрипта также не заменяет проверку на телефоне.

Краткая ручная проверка после сборки:

1. Убедитесь, что клавиатура появляется в «Заметках» и в поле HayKeys без «Полного доступа».
2. Проверьте `բ` во втором ряду, `պ` в четвёртом, отдельную `ւ`, постоянную `և`, удержание `ե` и `ւ`.
3. Проверьте однократный Shift, двойной Shift и выход из Caps Lock.
4. Зажмите удаление, отпустите палец и убедитесь, что удаление прекратилось.
5. Проверьте цифры, символы и возврат через `ԱԲԳ`.
6. Проверьте отсутствие смайлика и панели слов, ширину `123`, верхний отступ, нижний зазор, поворот iPhone и обе темы.
7. Вставьте в историю несколько текстов, перезапустите приложение, проверьте повторное копирование и удаление.
8. Проверьте звук: включён по умолчанию, затем отключите в приложении, примените и дождитесь подтверждения; закройте и снова откройте клавиатуру. Повторите с включением звука.
9. Переключитесь через 🌐 на другую клавиатуру и обратно.

В полях паролей и некоторых полях телефона iOS использует системную клавиатуру. Приложение также может запрещать сторонние клавиатуры. Это предусмотренное поведение платформы.

Подсказки ограничены встроенным списком слов. Автоматический выбор регистра в начале предложения, исправление ошибок, словарь уровня Gboard и собственная диктовка не реализованы. Клавиши и нижняя системная область могут выглядеть иначе, чем на исходном скриншоте; порядок букв сохранён.

## Если что-то не получилось

| Ситуация | Что сделать |
| --- | --- |
| iPhone отсутствует в Xcode | Разблокировать телефон, подтвердить доверие, проверить кабель и сопряжение в Device Hub. |
| Developer Mode disabled или пункта нет | Сначала установить SideStore через iloader. Если переключатель скрыт, использовать раздел «Если пункта „Режим разработчика“ нет» и команду amfi reveal-developer-mode с Ubuntu. |
| iOS телефона не поддерживается | Обновить Xcode до версии с поддержкой этой iOS; при необходимости обновить macOS. |
| Требуется команда разработчика | Выбрать одну и ту же Personal Team в Signing & Capabilities обоих targets. |
| Идентификатор занят | Задать свой HAYKEYS_BUNDLE_ID в Config/Personal.xcconfig. |
| Клавиатуры нет в настройках | Сначала установить и запустить HayKeys через Xcode, затем снова открыть список клавиатур. В проекте расширение уже добавлено в Embed App Extensions. |
| Вместо HayKeys появилась обычная клавиатура | Проверить через 🌐 в «Заметках». Поля паролей и приложения с запретом сторонних клавиатур используют системную. |
| Клавиатура перестала запускаться примерно через неделю | Заново установить тот же проект на iPhone через Xcode для обновления подписи. |

## Файлы проекта

- `App/` — приложение с инструкцией и полем проверки.
- `Keyboard/KeyboardViewController.swift` — интерфейс расширения и взаимодействие с полем ввода через UITextDocumentProxy.
- `Core/KeyboardLayout.swift` — раскладки; для изменения позиций редактируйте `letterRows`.
- `Core/KeyboardState.swift` — страницы клавиатуры и Shift / Caps Lock.
- `Core/WordSuggestions.swift` — встроенный словарь и дополнение слова.
- `Config/Personal.xcconfig` — базовый Bundle Identifier.
- `Tests/main.swift` — проверки логики без UIKit.
- `scripts/check_macos.sh` — запуск проверок и сборки на Mac.
- `scripts/test_core.sh` — проверки логики без UIKit; используются облачной сборкой.
- `scripts/build_unsigned_ipa.sh` — сборка приложения и расширения в неподписанный IPA на macOS runner.
- `.github/workflows/build-ipa.yml` — GitHub Actions, аккаунт Apple для сборки не нужен.
- `INSTALL_NO_MAC_RU.md` — отдельная инструкция для Ubuntu и SideStore.
- `INSTALL_RU.html` — та же инструкция в виде автономной страницы, которую удобно открыть в браузере.
